# Cost and unit economics

20 points — and the numeric spine of parameters 3, 4 and 8.**

Every figure here is arithmetic over
[`hardware/bom/RescueSwarm_BOM_India.xlsx`](../../hardware/bom/RescueSwarm_BOM_India.xlsx),

## 1. What the programme costs

| | INR |
|:--|--:|
| Air vehicle, **per aircraft** | 2.81 L |
| × 3 for the fleet | 8.44 L |
| Payload, ground segment, test equipment, spares, software | 15.62 L |
| **Subtotal** | **24.06 L** |
| Duty + freight, 22 % on the imported residual only | 2.05 L |
| GST, 18 % | 4.70 L |
| Contingency, 20 % | 6.16 L |
| **PROGRAMME TOTAL** | **36.97 L** |

**₹36.97 lakh is the funding ask.** Say plainly that it is a *competition build,
not a product*: it carries test and calibration equipment, a full spares set
including a possible fourth aircraft, and a field data campaign that a
production unit would not.

## 2. What an additional system costs

The programme total is the wrong number to quote a customer, because most of it
is one-off. What scales is the marginal cost.

| | INR |
|:--|--:|
| Marginal aircraft, taxes in | 3.60 L |
| Three-aircraft fleet | 10.81 L |
| Ground segment, one per fleet | 5.97 L |
| **Deployable system, cost basis** | **16.78 L** |

**Cost basis, not price.** Margin, warranty, training, support and
certification are commercial decisions and are not BOM arithmetic. Do not let
the deck blur the two — a panel will ask.

## 3. Indigenisation, quantified

**61.3 % Indian content, value-weighted across the priced BOM.** Not a slogan —
every line carries a declared Indian fraction, so the number is auditable.

| | INR |
|:--|--:|
| Programme as costed | 36.97 L |
| The same BOM fully imported | 41.56 L |
| **Saved by sourcing in India** | **4.59 L — 11 %** |

The saving is real but it is the smaller half of the argument. **The bigger half
is schedule:** the BOM's own note puts imports at 4–6 weeks against 2–3 weeks
domestic, inside a programme whose binding constraint is an **8-week flight-test
window**. Indigenisation buys flying days, and flying days are what the 600
flight points are made of.

This matters to the audience specifically — MeitY and the Drone Federation of
India — and it is one of the few claims in the deck that is measured rather than
asserted.

## 4. Recurring cost

The consumable that matters is **kits, not energy**. A sortie is a pack cycle
and a few rupees of electricity: 292 Wh, 15.3 min hover endurance against a
7.7 min design mission. The fleet carries 3 × 4 = **12 kits per sortie**.

Three things are genuinely unknown and are not guessed here:

- **Kit refill cost** — the BOM buys competition kits, not relief kits
- **Battery cycle life** at this C-rate in Indian ambient
- **Crew and transport** per deployment

## 5. What the pitch still needs, and from where

These are the remaining numbers. Each is a question for the team, not a gap to
fill with a plausible figure.

| Need | Parameter | Where it has to come from |
|:--|:--|:--|
| How many flood-response units exist, and their refresh rate | 3 — Market Sizing (30) | NDRF/SDRF establishment data; state disaster authority procurement records |
| What a buyer actually pays for comparable capability | 4 — Business Model (30) | Published tenders — GeM, state DM authority tenders |
| Cost per flight hour of the helicopter or boat search this displaces | 3, 4 | Published SAR operating costs |
| Funds raised, sponsors | 6 — Funds Raised (20) | ⏳ **lead time — start now, cannot be produced in the final week** |
| Partner conversations | 8 — Go-to-Market (20) | ⏳ **lead time** |
| DGCA category, BVLOS status, procurement cycle | 9 — Regulatory (10) | DGCA UAS Rules; state procurement process |

**A pitch that derives its cost from a real BOM and states which numbers are
unsourced is stronger than one that is confident throughout — because the first
can be checked.** Panels test confidence; they reward traceability.

## 6. Two defects found while building this

Recorded because they are the same failure mode the rest of this repository is
organised against, and because both produced *plausible* answers.

**Indigenisation first read as 0.0 %.** The column detector matched
`Indigenisation gap or action` — a prose column further right — instead of
`Indig. %`, because the loop kept overwriting on later matches. Zero percent is
a believable answer for a first draft, so it would very likely have shipped.
The model now refuses to run rather than report a zero it cannot justify.

**The BOM's own header still says `MTOW ~5.7 kg, fleet ~17 kg`.** The design
point is **6.36 kg / 19.08 kg**. It is descriptive text rather than a formula,
so nothing computed from it is wrong — but it is the third instance of a number
transcribed into prose and then left behind, and it is in the document that will
be handed to suppliers.
